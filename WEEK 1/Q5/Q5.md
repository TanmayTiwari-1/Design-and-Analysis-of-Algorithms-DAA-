# Partition Point Detection Using Linear Search and Binary Search

## Objective

The objective of this experiment is to determine the **partition point** (the index of the first occurrence of `1`) in an array consisting of consecutive `0`s followed by consecutive `1`s. The program compares the performance of **Linear Search** and **Binary Search** by counting the number of comparisons required to locate the partition point.

---

## Problem Statement

Given a sorted binary array of the form:

```
0 0 0 0 1 1 1 1 1
```

find the index of the **first occurrence of `1`**, which represents the partition point.

Implement two approaches:

1. **Linear Search** (Naive Approach)
2. **Binary Search** (Efficient Approach)

Compare their performance in terms of the number of comparisons performed.

---

## Features

- Implements Linear Search and Binary Search.
- Finds the first occurrence of `1` (partition point).
- Counts the number of comparisons made by each algorithm.
- Tests both algorithms on:
  - A small manually created array.
  - A large array containing **1,000,000** elements.
- Demonstrates the efficiency of Binary Search on sorted data.

---

## Algorithm

### Linear Search

1. Start from the first element.
2. Compare each element with `1`.
3. Stop when the first `1` is found.
4. Return its index.

---

### Binary Search

1. Set:
   - `low = 0`
   - `high = n`
2. Find the middle element.
3. If the middle element is `1`, continue searching the left half.
4. Otherwise, search the right half.
5. Continue until `low == high`.
6. Return the first occurrence of `1`.

## Working Principle

### Linear Search

Checks every element one by one until the first `1` is encountered.

Example:

```
0 0 0 0 1 1 1

Comparisons:

0
0
0
0
1 ← Stop
```

Time increases linearly with the size of the array.

---

### Binary Search

Since the array is sorted (all `0`s followed by all `1`s), Binary Search repeatedly divides the search space into two halves.

Example:

```
0 0 0 0 1 1 1 1

          Mid
           ↓
0 0 0 0 1 1 1 1

Search Left

      Mid
       ↓
0 0 0 0

Search Right

Partition Found
```

Only a few comparisons are required even for very large arrays.

---

## Time Complexity

### Linear Search

| Case | Complexity |
|------|------------|
| Best Case | O(1) |
| Average Case | O(n) |
| Worst Case | O(n) |

---

### Binary Search

| Case | Complexity |
|------|------------|
| Best Case | O(1) |
| Average Case | O(log n) |
| Worst Case | O(log n) |

---

## Space Complexity

Both algorithms use only a constant amount of extra memory.

```
Space Complexity = O(1)
```

## Experimental Analysis

### Small Test Case

Array:

```
0 0 0 0 1 1 1 1 1
```

Expected partition index:

```
4
```

Both algorithms correctly identify the partition point.

---

### Large Test Case

Array Size:

```
1,000,000
```

Partition Index:

```
333333
```

Observations:

- Linear Search performs hundreds of thousands of comparisons before finding the first `1`.
- Binary Search requires only about **log₂(1,000,000) ≈ 20** comparisons.
- The performance difference becomes significant as the array size increases.

---

## Comparison

| Feature | Linear Search | Binary Search |
|----------|---------------|---------------|
| Requires Sorted Array | No | Yes |
| Best Case | O(1) | O(1) |
| Average Case | O(n) | O(log n) |
| Worst Case | O(n) | O(log n) |
| Suitable for Large Sorted Arrays | No | Yes |

---

## Conclusion

The experiment demonstrates that although both algorithms correctly locate the partition point, **Binary Search** is significantly more efficient because it exploits the sorted structure of the array. While Linear Search requires a number of comparisons proportional to the array size (**O(n)**), Binary Search reduces the search space by half in each iteration, resulting in **O(log n)** time complexity. For large datasets, Binary Search is vastly superior and should be preferred whenever the data is sorted.
