# Duplicate Element Detection Using Brute Force

## Objective

The objective of this experiment is to determine whether an array contains duplicate elements using the **Brute Force** approach. The program counts the number of element comparisons performed while searching for duplicate elements and records the results for different array sizes. The generated data can be used to analyze the algorithm's performance and time complexity.

---

## Problem Statement

Given an array of integers, determine whether the array contains duplicate elements.

Implement the **Brute Force** algorithm by comparing every element with all subsequent elements. Measure the number of comparisons required and determine whether any duplicate element exists.

The results are stored in a CSV file for analysis and graph plotting.

---

## Features

- Implements duplicate detection using the Brute Force approach.
- Generates random arrays of different sizes.
- Counts the number of element comparisons.
- Detects whether duplicate elements exist.
- Stores experimental results in a CSV file.
- Displays the results on the console.

---

## Algorithm

1. Initialize the random number generator.
2. Create a CSV file named `comparisons.csv`.
3. For array sizes from **100** to **5000** (increment of 100):
   - Generate an array containing random integers.
   - Compare every element with all subsequent elements.
   - Increment the comparison counter for every comparison.
   - If a duplicate is found, terminate the search immediately.
   - Record:
     - Array size
     - Number of comparisons
     - Whether a duplicate was found
4. Store the results in the CSV file.
5. Close the file.
6. Display a success message.

---

## Brute Force Method

For every element:

- Compare it with every element that comes after it.
- If any two elements are equal, a duplicate is found.
- Otherwise, continue until all pairs have been checked.

Example:

```
Array:

5  8  2  9  8

Compare:

5 with 8,2,9,8
8 with 2,9,8 ← Duplicate Found
```

The algorithm stops immediately after detecting the duplicate.

## Observations

- The algorithm compares each element with every subsequent element.
- As soon as a duplicate is found, the algorithm terminates.
- Because the arrays are randomly generated, duplicates are usually found much earlier than the worst case.
- Consequently, the number of comparisons varies significantly between different executions.
- For the array of size **200**, no duplicate was found, so the algorithm performed all possible comparisons.

---

## Worst-Case Analysis

If no duplicate exists, every possible pair of elements must be compared.

The maximum number of comparisons is:

```
n(n − 1) / 2
```

For example:

| Array Size | Maximum Comparisons |
|-----------:|--------------------:|
| 100 | 4,950 |
| 200 | 19,900 |
| 500 | 124,750 |
| 1000 | 499,500 |
| 5000 | 12,497,500 |

---

## Time Complexity

### Best Case

A duplicate is found during the very first comparison.

```
O(1)
```

---

### Average Case

Depends on the distribution of duplicate elements.

```
Approximately O(n²)
```

---

### Worst Case

No duplicate exists.

Every pair of elements is compared.

```
O(n²)
```

---

## Space Complexity

The algorithm uses only a few extra variables.

```
Space Complexity = O(1)
```

---

## Experimental Analysis

The experimental results show:

- Arrays containing duplicates often require **far fewer comparisons** than the theoretical worst case because the search terminates immediately after finding the first duplicate.
- The array of size **200** required **19,900 comparisons**, which equals the theoretical maximum for 200 elements, indicating that no duplicate was present.
- For most other array sizes, duplicates were detected much earlier, reducing the number of comparisons significantly.

## Conclusion

The experiment demonstrates the working of the Brute Force approach for duplicate detection. The algorithm is simple and requires constant extra memory, but its worst-case time complexity is **O(n²)** because every pair of elements may need to be compared. In practice, when duplicate elements occur early in the array, the algorithm terminates sooner, resulting in significantly fewer comparisons than the theoretical worst case. However, for large datasets, more efficient techniques such as sorting or hashing are preferred due to their lower time complexity.
