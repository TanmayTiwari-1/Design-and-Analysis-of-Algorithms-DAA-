2-Way vs 3-Way Merge Sort

Overview

This project compares standard 2-way Merge Sort with a modified 3-way Merge Sort.

Both algorithms sort an array using divide-and-conquer, but they differ in how the input is divided:

2-way Merge Sort: divides the array into 2 parts.

3-way Merge Sort: divides the array into 3 parts.

The program measures:

Number of element comparisons

Execution time

Performance for different input sizes

It also verifies that both algorithms produce correctly sorted arrays.

Algorithms

1. Standard 2-Way Merge Sort

The array is repeatedly divided into two halves.

             Array
            /     \
        Left       Right
        / \         / \
       ... ...     ... ...

The sorted subarrays are then merged.

Time Complexity

The recurrence is:

T(n) = 2T(n/2) + O(n)

Therefore:

T(n) = Θ(n log n)

2. Modified 3-Way Merge Sort

The array is divided into three approximately equal parts.

              Array
           /    |    \
         A      B      C
        / \    / \    / \
       ...    ...    ...

The three sorted parts are then merged into one sorted array.

Time Complexity

The recurrence is:

T(n) = 3T(n/3) + O(n)

Therefore:

T(n) = Θ(n log n)

Thus, both algorithms have the same asymptotic time complexity, although their actual comparison counts and measured execution times can differ.

Implementation Details

The program uses a temporary array during merging.

2-Way Merge

Two sorted portions are compared element by element:

Left + Right → Sorted Array

Each comparison increments the comparisons counter.

3-Way Merge

Three sorted portions are merged.

While all three portions contain elements, the smallest of the three front elements is selected. This requires up to two comparisons for each selection.

When only two portions remain, the program uses ordinary 2-way merging.

For very small ranges (n < 3), the implementation falls back to a 2-way split.

Expected Results

Since both algorithms have:

Θ(n log n)

their growth rates should be similar as n increases.

However, the actual number of comparisons can differ because the 3-way merge has to determine the smallest element among three active runs. Therefore, asymptotically identical algorithms do not necessarily have identical constants or measured performance.

The experimental graphs allow the theoretical analysis to be compared with the actual measurements.

Conclusion

Both standard 2-way Merge Sort and the modified 3-way Merge Sort have the same asymptotic time complexity:

Θ(n log n)

The main difference is the way the input is divided and merged.

The experiment compares their comparison counts and execution times to determine how these implementation choices affect practical performance.
